## 0. 背景与目标

项目定位从"刷题系统"升级为"AI 备考教练"：不仅要正确率，还要回答"这道题在考什么、我为什么不会、该补什么"。

P0 交付后，用户每天刷题可以获得：

- 每题的**作答把握程度**与**障碍原因**记录（答对但靠猜的题也被识别）
- 每题的 **AI 考点拆解卡**（五段式，缓存复用）
- 主动标记的**掌握状态**与由此驱动的**待巩固队列**和诊断统计

### 非目标（明确不做，防蔓延）

- ❌ 全量 1000 题批量预生成拆解（按需生成 + 缓存）
- ❌ 举一反三互动练习（P0 只出"延伸思考题"文本，不做作答交互）
- ❌ 掌握状态自动推断（只信用户主动标记）
- ❌ 官方文档核实状态自动化（只展示 `sources` 链接 + 免责声明）
- ❌ 替换 `errorType` 五分类（保留兼容旧记录）

## 1. 数据模型（app/src/core.js）

### 1.1 attempt 扩展（每次作答追加，随现有 attempts 数组走）

```js
{
  ok: true/false,
  at: <ts>, chosen: [...], duration: <ms>,
  // —— FR-013 新增（可缺省 = 未标记）——
  confidence: 'sure' | 'eliminate' | 'guess',   // 维度A：确定理解/靠排除/基本靠猜
  obstacles: ['knowledge_gap'|'term'|'unclear_goal'|'cannot_apply'|'confused'|'misread']  // 维度B 多选
}
```

- **答对也可标记**（这是与 errorType 的本质区别：errorType 只存在于错题）
- 旧记录无这两字段 → 视为"未标记"，一切推导函数对 undefined 安全

### 1.2 record 扩展（题目粒度）

```js
{
  attempts: [...], streak, favorite, errorType?,      // 全部保留
  mastery: 'understood' | 'partial' | 'lost',          // 三档掌握状态（用户主动标记）
  masteryAt: <ts>                                      // 标记时间，用于排序与展示
}
```

### 1.3 推导函数（纯函数，进 core.js，全部带单测）

| 函数 | 语义 |
| --- | --- |
| `needsConsolidation(record)` | 待巩固 = mastery ∈ {partial, lost}；**或**最近一次 attempt.confidence === 'guess' 且此后没有标记 understood |
| `luckyCorrect(record)` | 蒙对 = 最近一次 attempt.ok === true 且 confidence === 'guess' |
| `obstacleStats(records)` | 障碍分布计数（用于诊断卡）；按题目去重（每题取最近一次标记） |
| `masteryStats(records)` | 三档分布计数 |

### 1.4 兼容与合并

- 旧 progress.json 不迁移、不改写——新字段全部可选
- 多端合并沿用现有 revision 乐观锁（整份 state PUT），attempt 数组自然携带新字段
- `errorType` 语义不变；诊断统计里与 obstacles 并列展示（新维度为主，旧维度兜底）

## 2. API 设计（app/server.py + app/ai/）

### 2.1 新增 `POST /api/ai/breakdown`

```json
// 请求（答题提交后才允许调用——前端控制；P0 不做服务端状态校验）
{ "questionId": "FDE-M1-001" }
// 响应（结构化拆解，缓存命中秒回）
{
  "questionId": "FDE-M1-001",
  "prompt_version": "v1",
  "exam_focus": "……考察目标与关键条件……",
  "knowledge": [ {"term": "RAG", "desc": "……一句话职责"} ],
  "reasoning": "……解题思路与关键判断……",
  "why_others": [ {"option": "A", "reason": "……"} ],
  "extension": "……举一反三思考题……",
  "cached": false
}
```

- 复用 `ai/service.py` 调用链；cache_key = `'breakdown:' + questionId`（与 explain/term 键空间隔离）
- 限额：`BREAKDOWN_DAILY_LIMIT = 30/天`（独立计数，新增 `_USAGE_KEYS` 第三项 `'breakdown_usage'`），命中缓存不计额
- 校验：questionId 必须存在（404），请求体长度/键校验同现有 term 路由
- 防护继承：X-FDE-Client 头 + Origin 同源 + Host 白名单（现有三重防护不动）

### 2.2 Prompt（app/ai/prompts.py）

- `BREAKDOWN_PROMPT_VERSION = 'v1'`；`BREAKDOWN_REQUIRED_FIELDS = ('exam_focus','knowledge','reasoning','why_others','extension')`
- 输入：题干、选项、**标准答案、官方 explanation、distractors、topic、sources**（拆解在提交后展示，允许带答案——与 term 的防泄题约束相反，注意不要复用 _TERM_SYSTEM）
- 输出要求：JSON、中文、knowledge 为数组且每项一句话、why_others 覆盖全部错误选项、exam_focus 必须区分"知识点"与"考点"（考察什么判断）
- 解析复用 `client.py extract_json`（raw_decode，已修尾部复述问题）

### 2.3 状态保存

不新增接口——confidence/obstacles/mastery 全部随 `/api/state` PUT 走（服务端对 state 是不透明 JSON + revision 锁）。

## 3. UI 设计（app/src/app.js + styles.css）

### 3.1 答题后自评条（练习模式，提交答案后出现，可跳过）

- 一行三选：「确定理解 / 靠排除法 / 基本靠猜」——单选，点击即存入当前 attempt，可改
- 障碍 chips（多选）：知识盲区 / 术语不懂 / 考点不明 / 不会应用 / 概念混淆 / 审题失误——折叠收起，点开展开（默认收起，降低摩擦）
- **手机输入注意**：chips 用 button 不触发 iOS 缩放（已修 16px 规则，新控件一律 button/≥16px）

### 3.2 考点拆解卡（反馈区折叠卡，点「AI 考点拆解」按钮懒加载）

- 加载态文案（glm-5.3-flash 首次 ~20-35s，需 loading 提示）；错误态可重试；命中缓存秒显
- 底部固定免责行："AI 解析不等于官方标准答案"+ sources 链接列表
- 结构按五段渲染：考什么 → 知识点表 → 解题思路 → 干扰项 → 举一反三

### 3.3 掌握状态三档（拆解卡/反馈区底部）

「已理解 / 部分理解 / 仍然不懂」三个按钮，点击写 record.mastery + masteryAt，toast 确认，可覆盖改标

### 3.4 考试模式遮罩（硬约束）

- 正式模拟考（attempt.mode === 'exam'）：**不显示**自评条、拆解卡、掌握按钮
- 交卷后的考试报告/回顾页：逐题可见拆解卡与自评入口

### 3.5 诊断统计（进度页新增"诊断"卡）

- 数字：蒙对题数、待巩固队列数、障碍分布 top3、掌握三档分布
- 入口：「待巩固队列」练习按钮（P0 = 队列内顺序练习，沿用现有练习渲染）

## 6. 验收标准（P0 Definition of Done）

1. 练习模式答完一题 → 可标记把握程度（含答对）与多选障碍，刷新后仍在
2. 答题提交后 → 拆解卡五段齐全，二次打开同题秒显（缓存），sources + 免责声明可见
3. 掌握状态可标记/改标；「部分理解/仍然不懂/蒙对」进入待巩固队列，进度页数字正确
4. 模拟考中三者全隐藏；交卷后回顾页可见
5. 旧 progress.json 打开无异常、旧错题 errorType 照常显示
6. 手机（serve 链路）全流程可用；限额 30/天生效且缓存不耗额度
7. node + python 全量回归绿

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 输出结构漂移（缺字段/多余文本） | REQUIRED_FIELDS 硬校验（同 explain 模式）+ raw_decode；失败返回可重试错误，不写缓存 |
| 首次拆解 20-35s 太慢影响体验 | 懒加载 + loading 文案；拆解不阻塞下一题；缓存后秒回 |
| 手机 PWA 又吃旧缓存 | 每批交付递增 UI_BUILD；验收先看右下角构建号；Safari `?v=` 强刷法已沉淀 |
| 限额耗尽 | 前端明确文案"今日 AI 拆解额度已用完（30 题），明日重置/缓存不限" |
| 20 天窗口被 P1 功能挤占 | 严格按非目标清单砍需求；统计图表化等一律 P1 |
| attempt 数组膨胀 | obstacles/confidence 字段极小；progress.json gzip 已开（state 本身 no-store 但体量小） |
