## 0. 目标与非目标

P0 交付：做完每道题后，用户**立刻**能看到（不等待、不耗额度）——这道题考什么、涉及哪些知识、为什么每个选项对/错；并可标记把握程度、障碍原因、掌握状态；诊断出蒙对题与待巩固队列。

### 非目标（P0 明确不做）

- ❌ 全量 1000 题批量预生成拆解（按需 + 缓存）
- ❌ 举一反三互动练习（只出思考题文本）
- ❌ 掌握状态自动推断（只信主动标记）
- ❌ 官方文档核实状态自动化（只展示 sources + 免责声明）
- ❌ 替换 `errorType` 五分类（保留兼容）
- ❌ "我还是不理解"追问入口（P1，见 §9）

## 1. 数据模型（app/src/core.js）——评审修正 #1

### 1.1 attempt 扩展（沿用现有字段，只新增可选键）

现有（core.js recordAnswer 实际写入）：`{at, answers, correct, questionVersion, mode}`

```js
// —— FR-013 新增（全部可缺省 = 未标记）——
confidence: 'sure' | 'eliminate' | 'guess',  // 维度A 把握程度（答对也可标记）
obstacles: [...],                            // 维度B 多选：knowledge_gap/term/unclear_goal/cannot_apply/confused/misread
selfEvalAt: <ts>                             // 自评写入时间（合并依据，v2 新增）
```

### 1.2 record 扩展

```js
mastery: 'understood' | 'partial' | 'lost',  // 三档掌握状态
masteryAt: <ts>,                             // 标记时间
masteryVersion: <questionVersion>            // 标记时的题目版本（题目更新后"已理解"失效，v2 新增）
```

### 1.3 mergeBackup 修复（v2 必修，多端不丢标签）

现状（core.js:161）：attempt 去重键 `at + questionVersion + answers`，保留**先出现**的副本——事后补的自评标签会在多端合并时被无标签副本覆盖。修复：

- 同键 attempt 合并：`confidence/obstacles/selfEvalAt` 取 `selfEvalAt` 较大的一方（缺失视为 0）
- record 级：`mastery/masteryAt/masteryVersion` 取 `masteryAt` 较大的一方；`favorite` 维持现有 OR
- 新增单测：**A 端作答+补标签 ↔ B 端同题作答无标签，双向合并标签都不丢**

## 2. 考点速览（本地默认展示，零等待零额度）——评审修正 #2

提交答案后反馈区**自动展开**速览卡（不点按钮、不等 AI、不耗额度）：

| 区块 | 数据源 | 降级策略 |
| --- | --- | --- |
| 这道题考什么（一句话） | AI 拆解缓存的 `exam_focus`（v2.1：题库实测无显式考点字段，首开显示“待生成”，拆解后直接展示） | 无缓存 → “考点待 AI 拆解生成”，**绝不拿 topic 主题名冒充考点** |
| 涉及哪些知识点 | `topic` 标签 + `sources` 链接 | 始终可显示 |
| 为什么选这个答案 | 官方 `explanation` + `distractors` | 始终可显示（现有数据即齐） |
| 为什么其他选项不合适 | `distractors` | 同上 |

AI 深度拆解按钮（§3）位于速览卡底部——点开后生成五段式（考什么/知识表/解题思路/干扰项/举一反三）。

> 2026-11-03 用户反馈交互调整（1103c）：题目操作栏新增常驻「考点速览」按钮（与「查术语」同排，练习模式随时可点）。提交前抽屉只展示“考什么 + 知识点”（不泄答案线索）；提交后同一抽屉解锁 AI 深度拆解与掌握标记；提交后题面下方的默认速览卡保留。

## 3. AI 深度拆解（按需生成 + 版本化缓存）——评审修正 #4/#5

### 3.1 API `POST /api/ai/breakdown`

请求 `{questionId, contentHash}`；响应五段结构（exam_focus/knowledge/reasoning/why_others/extension）+ `prompt_version` + `cached`。

### 3.2 缓存键（v2.1 修正 #8：覆盖存量机制）

```
cache_key(question_id, content_hash, answers, model, prompt_version)   # explain/term 存量键同步补列
breakdown:{questionId}:{contentHash}:{model}:{promptVersion}            # 新接口同规则
```

- **存量修复**：`ai/store.py cache_key()` 现无 prompt_version 列 → 本次统一补上，此后升 Prompt 即自动失效旧缓存（v1.1 升级对旧缓存的实际失效也依赖本项）
- breakdown 的 contentHash 以**服务端题库 `review.contentHash` 为准**，不信任客户端传入
- 改题、换模型、升 Prompt → 旧缓存自然失效，绝不返回过期拆解

### 3.3 输出校验加深（v2 修正）

不止校验 5 个顶层字段：`knowledge` 必须非空数组且每项含 `term/desc` 非空字符串；`why_others` **必须覆盖全部错误选项（数量 = 选项数 - 1）**且 option 键合法；`extension` 非空。校验失败不写缓存、返回可重试错误。

### 3.4 X-FDE-Client 补齐（v2 修正：v1 误称已继承）

- 前端：app.js 的 explain/term/breakdown fetch 全部补 `X-FDE-Client: offline-study`（现在只有 store.js:8 的 PUT 带）
- 服务端：`do_POST` 增加 `X-FDE-Client != 'offline-study' → 403`（与 do_PUT 一致）
- 测试：无头 403 用例 ×3 路由

### 3.5 Prompt 与限额

- `BREAKDOWN_PROMPT_VERSION='v1'`（FDE 全称已修正为 Forward Deployed Engineer）；拆解在提交后展示，**允许携带标准答案/解析/distractors/topic/sources**（与 term 防泄题约束相反，不复用 `_TERM_SYSTEM`）
- 限额 30/天独立计数（`breakdown_usage`），缓存命中不计额

## 4. 交互与考试隔离——评审修正 #5

- 练习模式：提交后 → 速览卡自动展开 → 自评条（把握程度单选一行；障碍 chips 折叠多选）→ 掌握三档按钮（写 record.mastery*）
- **模拟考（mode='exam'）：自评/速览/AI 拆解/掌握按钮全部隐藏**
- **考试报告 `renderResult()` 逐题复盘（v2 新增）：补自评入口 + 速览卡 + AI 拆解 + 掌握按钮**（交卷后可见）
- 手机适配：新控件一律 button（不触发 iOS 缩放），遵循 16px 输入规则

### 4.5 历史作答与解析查看（v2.1 补丁 #10）

现状：`submitted` 为内存变量，切题即 `resetQuestion()`，重开已做题无法直接看解析——待巩固队列上线后此问题会放大。修复：

- 打开已做题时提供「查看上次作答与考点解析」入口：从 `attempts` 末条渲染历史答案 + 速览卡 + AI 拆解（有缓存则展示），**不创建新 attempt**
- 另设「重新练习」按钮：进入作答态，真实提交才追加 attempt
- 复习两条路径自由选择：先回顾知识，或先重测自己

## 5. 待巩固队列与诊断——评审修正 #3

### 5.1 入队条件（`needsConsolidation(record, currentVersion)`，任一满足）

1. 最近一次作答**答错**
2. 最近一次作答 `confidence ∈ {guess, eliminate}`
3. 最近一次作答标记了 `obstacles`（非空）
4. `mastery ∈ {partial, lost}`
5. **当前版本未确认掌握**（v2.1 #9）：有作答记录，但 `masteryVersion ≠ 当前 contentHash` 或从未在当前版本标记 understood（覆盖旧版已理解+题目改版场景）

### 5.2 解除规则

- 仅当用户**在最新一次作答之后**标记 `understood`（`masteryAt ≥ last.at`，同毫秒也算之后）**且** `masteryVersion === 当前 questionVersion`，条件 1–3、5 解除
- 条件 4 天然随标记解除
- **新一轮作答再暴露障碍 → 自动重新入队**（规则天然覆盖）
- **题目内容更新（contentHash 变化）→ 旧"已理解"失效**，题目重回待巩固

### 5.3 诊断统计（进度页诊断卡）

蒙对题数（luckyCorrect = 最近一次 correct 且 guess）、待巩固队列数、障碍分布 top3、掌握三档分布；待巩固队列一键练习入口。

## 8. 验收标准（DoD，v2 扩为 9 条）

1. 练习模式答完一题 → **速览卡自动展示**（考什么降级提示/知识点/官方解析/干扰项），无 AI 等待
2. 自评条可标记把握程度（含答对）与多选障碍；**刷新/多端合并后标签不丢**（A 端补标 ↔ B 端无标双向验证）
3. AI 深度拆解五段齐全；同题二次打开秒显；**改题/换 Prompt 后旧缓存不命中**
4. 掌握状态可标记/改标；按 §5 规则进/出待巩固队列；**题目版本更新后旧"已理解"失效**
5. 模拟考中自评/速览/拆解/掌握全隐藏；**交卷后 renderResult 复盘页逐题可见**
6. 旧 progress.json 无异常、errorType 照常
7. AI 三路由无 X-FDE-Client 一律 403；拆解限额 30/天生效、缓存不耗额
8. 手机（serve 链路）全流程可用
9. node + python 全量回归绿
10. **学习挽回指标（v2.1 新增）**：同一题从障碍状态（靠猜/知识盲区/考点不明）→ 学习后重新答对且标记已理解的比例可统计展示（诊断卡“挽回率”），作为 FR-013 是否真正有效的核心验收指标
