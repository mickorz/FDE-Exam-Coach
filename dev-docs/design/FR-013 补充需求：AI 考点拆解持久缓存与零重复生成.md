# FR-013 补充需求：AI 考点拆解持久缓存与零重复生成

**版本：** V1.0  
**优先级：** P0  
**项目：** FDE-Exam-Coach  
**目标：** 一道题的完整考点拆解成功生成并保存后，后续查看无需再次调用大模型。

## 1. 问题背景

当前服务端已有 AI 拆解缓存机制，但前端只持久保存考点摘要，不会自动恢复完整五段式解析。重新进入题目仍需点击按钮请求服务端，容易造成重复生成的感受，也缺少对真实缓存未命中和重复 Token 消耗的充分诊断。

## 2. 功能需求

### FR-013-CACHE-01：完整结果持久化

- 复用 `local-data/ai-explanations.json`。
- 保存完整五段式解析：考点、知识点、解题逻辑、错误选项、举一反三。
- 成功写入缓存后才返回生成成功。
- 页面刷新、服务重启后仍能读取。

### FR-013-CACHE-02：自动读取缓存

- 新增 `GET /api/ai/breakdown?questionId=...`。
- GET 只读取缓存，不得调用 AI。
- 用户重新进入已做题时，自动查询并展示完整结果。
- 未命中时显示生成按钮，不自动消耗 Token。
- 本地考点摘要不能作为完整缓存已命中的唯一依据。

### FR-013-CACHE-03：缓存命中规则

缓存键包含：

`questionId + contentHash + model + promptVersion + 功能类型`

- 题目内容、模型及 Prompt 未变化时复用已有结果。
- 有效版本变化后不误用旧缓存。
- 不随意改变现有缓存键算法，避免已生成内容集体失效。
- 缓存命中不计入每日 30 次生成额度。

### FR-013-CACHE-04：并发去重

- 同一道题同时有多个生成请求，只启动一个生成任务。
- 其他请求等待并复用生成结果。
- 不同题目之间互不阻塞。
- 当前 P0 按单服务进程部署验收。

### FR-013-CACHE-05：失败处理

- AI 输出校验失败时，允许最多一次额外重试。
- 最终失败不标记为缓存成功。
- 缓存文件写入失败时明确报错。
- 禁止后台无限重试或自动重新生成。

### FR-013-CACHE-06：缓存状态提示

界面区分：

- 已读取缓存：本次 0 次 AI 调用。
- 尚未生成：可主动点击生成。
- 正在生成：显示加载状态。
- 缓存失效：提示版本变化。
- 生成失败：显示错误，可手动重试。

### FR-013-CACHE-07：考试及数据兼容

- 正式模拟考试中隐藏解析与生成入口。
- 交卷后可以在复盘页读取缓存。
- 不破坏现有学习记录和多端合并。
- 完整拆解不重复写入 `progress.json`。
- 缓存文件不能通过公开静态 URL 访问。

## 3. 验收标准

1. 首次成功生成：上游调用一次，缓存完整持久化。
2. 第二次查看同题：上游调用零次。
3. 页面刷新后查看：上游调用零次。
4. 服务端重启后查看：上游调用零次。
5. 手机和电脑同时首次生成：只启动一个生成任务。
6. 模型或题目版本变化：旧缓存不会误命中。
7. AI 生成失败：不得显示“已缓存”，不得无限重试。
8. 缓存读取不占用生成额度。
9. 正式模拟考试中不得提前显示拆解。
10. Node/Python 自动化回归和手机端验收通过。

验收必须检查真实上游调用次数，不能只依据界面文案判断是否命中缓存。

## 4. 开发顺序

**P0-A：** 排查真实缓存命中与重复调用情况。  
**P0-B：** 新增只读缓存 API 和前端自动展示。  
**P0-C：** 增加同键并发去重与错误诊断。  
**P0-D：** 完成刷新、重启、多设备、异常及考试隔离测试。

## 5. 非目标

本次不引入 Redis、向量数据库、云缓存，不批量预生成全部题目，不重构 AI 框架，也不开发复杂的多版本解析编辑器。

**最终交付目标：相同有效版本的考点拆解，成功生成一次，后续可直接反复学习，不重复消耗模型 Token。**
