# 腾讯云服务器部署需求文档（V1.0）

**日期：** 2026-10-30
**关联：** 《FDE Exam Coach 产品需求文档（PRD V1.0）》Phase 1；复用分析与技术选型报告
**性质：** Phase 1 附加需求——个人备考系统的云端私有部署（非 Phase 2 产品化）

---

## 一、背景与目标

P0 备考系统已在本地可用（`app/`，Python 标准库 + 原生 JS）。用户希望将同一套系统部署到自己的腾讯云服务器上，达成：

1. **随时随地处备考**：通过域名在浏览器访问（家里电脑、手机、办公室），学习记录集中在服务器，不依赖某台电脑开机。
2. **快速迭代发布**：每次开发完成，一条命令即可把最新版本发布到服务器，不手工折腾。
3. **数据安全**：学习记录与 AI 配置是个人资产，不能公开可写、不能泄露 API Key。

## 二、已有条件

| 条件 | 说明 |
|---|---|
| 腾讯云服务器 | 有公网 IP，提供 SSH 与 FTP |
| 域名 | 已有，可解析到公网 IP |
| 代码仓库 | GitHub 公开仓库 mickorz/FDE-Exam-Coach（main 分支，随开发推送） |
| 应用形态 | 无状态静态前端 + 单进程 Python 标准库服务（端口可指定），数据落盘 `app/local-data/` |

## 三、需求场景

### 场景 A：域名访问

浏览器输入域名即可打开备考系统，全程 HTTPS；首次访问输入一次网站密码（由服务器反向代理校验），之后浏览器记住凭据。

### 场景 B：一键发布

开发机上的日常工作流：

```text
改代码 -> 测试通过 -> deploy 一条命令（git push + 服务器 git pull + 重启服务）-> 域名立即生效
```

发布过程不得触碰服务器上的 `local-data/`（学习记录与 AI 配置）。

### 场景 C：服务常驻

服务器重启后应用自动拉起；进程崩溃自动重启。

## 四、安全需求（必须）

1. **访问认证**：应用自身无登录系统，写接口（保存学习记录）与 AI 接口（消耗额度）必须置于密码认证之后，避免公网任意读写与盗刷 AI 额度。
2. **传输加密**：全程 HTTPS，自动申请与续期证书。
3. **网络边界**：应用进程只监听 127.0.0.1，仅反向代理可达；不直接暴露应用端口。
4. **密钥隔离**：AI API Key 只存在于服务器 `local-data/config.json`（gitignore），永不下发浏览器、不进 git。
5. **同源保护**：保留并扩展现有 Host 白名单与写操作同源校验（`--allowed-host` 放行部署域名，兼容 HTTPS 反代）。
6. **传输通道**：部署与运维只走 SSH；FTP 为明文协议，禁止用于部署与传输凭据。

## 五、部署前提（腾讯云侧检查项）

| 检查项 | 要求 |
|---|---|
| ICP 备案 | 大陆服务器上域名走 80/443 必须已备案；未备案则 80/443 被平台拦截（备选方案见附录） |
| 安全组 | 入站放行 80（证书签发与跳转）、443（HTTPS） |
| DNS | 域名 A 记录指向公网 IP |
| 服务器软件 | Python 3.9+（Ubuntu/Debian 自带）、Caddy（反向代理，自动 HTTPS + 密码认证）、git |

## 六、方案概述

```text
浏览器 --HTTPS+密码--> Caddy(443, 自动证书, basic auth) --反代--> server.py(127.0.0.1:8765, --allowed-host 域名)
                                                        数据落盘 /opt 下 app/local-data/
开发机 Windows --SSH--> 服务器 git pull + systemctl restart
```

组件选择理由：

- **Caddy 而非 nginx+certbot**：一个配置文件同时解决自动 HTTPS、密码认证、反向代理；无默认超时限制（AI 讲解最长 60 秒不被掐断）；免维护续期脚本。
- **git 拉取而非 FTP/SCP 上传**：发布内容与仓库提交一致，可回滚；天然避开 local-data（gitignore）。

## 七、验收标准

1. `https://域名` 打开备考系统，密码认证生效；HTTPS 证书有效且自动续期。
2. 刷题、模拟考试、错题、AI 讲解全功能可用；学习记录保存在服务器 `local-data/progress.json`。
3. 未认证请求不能读写任何数据；应用端口（8765）从公网不可达。
4. `deploy` 一条命令完成发布，发布后 `local-data/` 内容不变。
5. 服务器重启后服务自动恢复。
6. 本地开发模式行为不变（不传 `--allowed-host` 时仅本机可访问，现有测试全绿）。

## 八、范围外（明确不做）

- 多用户、注册、权限系统（Phase 2 范畴）。
- 云数据库迁移：继续使用本地 JSON 文件 + 原子写入。
- 应用内登录系统：认证由反向代理层承担。
- 自动化 CI/CD 流水线：单机场景一条 SSH 命令足矣。

## 九、风险与注意事项

| 风险 | 应对 |
|---|---|
| 本机与服务器两份学习记录分叉 | 服务器作为唯一主学习入口；本地仅离线应急，使用数据备份页"导入并合并"回传服务器 |
| 服务器数据丢失 | 每日 cron 打包 `local-data/`；重大节点手动用应用内"导出学习备份"下载留存 |
| 域名未备案导致 80/443 不可用 | 备选：换香港区域服务器，或临时用非标准端口 + 自签证书（体验降级，仅应急） |
| AI 讲解长耗时被代理掐断 | 选型 Caddy（默认无响应超时）；若换 nginx 需调大 proxy_read_timeout |
| 服务器被扫描探测 | basic auth + 应用仅监听回环 + 腾讯云安全组最小化放行 |
