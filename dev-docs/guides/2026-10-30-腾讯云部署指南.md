# 腾讯云部署指南

**需求文档：** `dev-docs/design/2026-10-30-腾讯云服务器部署需求.md`
**目标：** 域名 HTTPS + 密码访问备考系统；每次开发完一条命令发布。

## 架构

```text
浏览器 --HTTPS+密码--> Caddy(443, 自动证书, basic auth)
                          | 反向代理
                          v
                 server.py(127.0.0.1:8765, --allowed-host 域名)
                          | 原子写入
                          v
                 /opt/fde-exam-coach/app/local-data/  (学习记录 + AI 配置)
```

## 前提检查（缺一不可）

1. **ICP 备案**：大陆服务器域名走 80/443 必须已备案，否则腾讯云拦截端口（未备案见文末备选）。
2. **安全组**：腾讯云控制台 -> 轻量/CVM -> 防火墙/安全组，放行入站 TCP 80、443。
3. **DNS**：域名添加 A 记录 -> 公网 IP。
4. **SSH 免密（可选但推荐）**：开发机 `ssh-keygen` 后将公钥追加到服务器 `~/.ssh/authorized_keys`，发布脚本才能无人值守。

## 一次性初始化（服务器上执行）

```bash
# 1. 上传初始化脚本（走 scp，不用 FTP）
scp deploy/setup-server.sh 用户名@服务器IP:/tmp/

# 2. 在服务器执行（会提示输入域名、网站访问用户名和密码）
ssh 用户名@服务器IP
sudo bash /tmp/setup-server.sh 你的域名
```

脚本自动完成：安装 Caddy -> 克隆仓库到 `/opt/fde-exam-coach` -> 安装 systemd 服务（开机自启/崩溃重启）-> 生成 HTTPS 证书配置 -> 配置免密重启权限。

完成后浏览器访问 `https://你的域名`，输入步骤中设置的用户名密码即可刷题。

### 开启 AI 讲解（可选）

```bash
cd /opt/fde-exam-coach/app/local-data
cp config.json.example config.json
nano config.json        # 填入 api_key / base_url / model
```

## 日常发布（开发机 Windows）

```bat
deploy\deploy.bat 用户名@服务器IP
```

脚本行为：`git pull --rebase` -> `git push` -> SSH 到服务器 `git pull + 重启服务` -> 输出服务状态。全程不触碰服务器 `local-data/`。

注意：发布的是**已提交**的代码，改完代码先 commit 再执行；发布失败时脚本会明确报错，不会静默半更新。

## 数据安全与备份

- 学习记录在服务器 `/opt/fde-exam-coach/app/local-data/progress.json`，AI 配置与讲解缓存在同目录（均已 gitignore）。
- 每日自动备份（服务器 crontab -e 添加）：

```cron
30 3 * * * tar -czf /home/ubuntu/fde-backup-$(date +\%m\%d).tar.gz -C /opt/fde-exam-coach/app local-data
```

- 每周清理 30 天前的备份：`find /home/ubuntu -name 'fde-backup-*.tar.gz' -mtime +30 -delete`
- 重大节点（考前）：用应用内"数据备份"页导出一份 JSON 到本地留存。

## 双端使用注意

服务器上线后，**以服务器为主学习入口**。本地副本仅作离线应急；两端都产生作答后，在"数据备份"页导出一份、在另一端"导入并合并备份"（自动去重合并，可放心操作，导入前会自动下载快照）。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 域名打不开 | 检查顺序：DNS 解析生效 -> 安全组 80/443 放行 -> 域名是否已备案 -> `systemctl status caddy fde-coach` |
| 证书申请失败 | 80 端口不通（安全组/备案）或 DNS 未生效；Caddy 会自动重试 |
| AI 讲解报"尚未配置" | 服务器 `local-data/config.json` 未配置或格式错误 |
| 换域名 | 改 `/etc/caddy/Caddyfile` 与 `/etc/systemd/system/fde-coach.service` 的 `--allowed-host`，然后 `systemctl daemon-reload && systemctl restart fde-coach && systemctl reload caddy` |
| 服务器是 CentOS | 脚本按 Ubuntu/Debian 编写；CentOS 将 `apt-get` 换成 `dnf`，Caddy 改用官方 yum 源，其余步骤相同 |

## 为什么不用 FTP

FTP 是明文协议（账号密码、代码内容均裸奔），且无法保证与 git 提交一致。部署统一走 SSH + git 拉取；FTP 端口建议直接在安全组关闭。
